## Why

Release B closed on 2026-10-30: a wrong memory that a reviewed page corrects
is not a current answer in the next session. Only a CI test shows it. No one
can follow the loop from the docs: README's Install section is four lines,
the memkernel composition is spread over `docs/consumers.md` as API recipes,
and the host settings are in `docs/mcp-adapter.md`. The roadmap's Launch
sequence step 2 asks for two tested quickstarts and a short demonstration,
and neither exists. The integration measurement exists but tells nothing:
memkernel's preregistered 0.5.0 run included a `wiki_studio` arm on the five
`lc-wiki` tasks; it passed 25 of 25, and so did every arm, `bare` included,
because the runner copies the wiki into the second session for every arm.
The arm is wiki-studio 0.4.1 alone through the CLI, not the governed
composition the roadmap names. Issue #10 is open on a condition that is met,
and the README still points to it as pending.

This release is docs, tests, CI jobs and one example, released as 0.8.1
(D5): a standalone quickstart and a memkernel composition quickstart whose
commands are extracted from the pages and executed on clean installs; a
demonstration of an obsolete decision corrected through a reviewed proposal
and absent from the next session, run as a blocking CI job and once as a
recorded run bound to the bytes it executed; a design for a
governed-composition measurement that can discriminate the arms (stretch,
cut first); and an honest close of issue #10 by restatement with a successor
issue. No runtime behaviour or API change under `src/`; only the version
constant moves.

### US3 — the obsolete-decision demonstration

- **FR-011 (the script, D9, D16)**: `examples/correction-loop/demo.py` (new, with the two-line EGOGE / Apache-2.0 header) MUST run three steps, each a separate process (`sys.executable demo.py <step> --workdir DIR`) on one persisted memkernel store and one wiki under `--workdir`: `session-1`, `curator`, `session-2`; `python demo.py --workdir DIR [--summary PATH]` runs the three in order and stops at the first that fails. Each step runs with `--workdir` as its working directory. memkernel's settings come from environment variables the orchestrator passes to each step (`MEMKERNEL_PROJECT_ROOT` set to `--workdir`, `MEMKERNEL_PROJECT_ID`, `MEMKERNEL_CHROMA_PERSIST_PATH`, `MEMKERNEL_WIKI_DIR`, `MEMKERNEL_WIKI_PROPOSALS_DIR` as FR-007; the embedding from the caller's environment); memkernel is driven through the Python calls its tools make (FR-006); the curator uses the `wiki-studio` CLI found beside `sys.executable`.
