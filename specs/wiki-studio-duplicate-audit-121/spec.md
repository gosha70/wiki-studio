## Why

Issue 121 asks for a way to tell a curator that two pages record the same
thing. Cycle 11 shipped a hint at writing time: `propose` lists the 5 most
similar pages of the same type. Nothing reports pairs already in the wiki. The
owner kept the issue open for that: a model-free `findings` kind that flags two
existing pages that may say the same thing. A finding shows on every run, so it
has to be right more often than wrong.

The rule tried here is **mutual rank**: two same-type pages are flagged when
each is in the other's top k under the hint's own ranker, at k = 1, 3 or 5. An
external review showed that mutual rank without a floor flags about half of any
wiki (pitch, finding 10). So the work is measured first, in stages that can each
end it:

1. **The protocol** (US1): the candidates, the index rule, the bar, the
   held-out rules and the stop rule, written down and signed off by the owner
   before any score exists.
2. **The development stage** (US2-US3): the three candidates run once on cycle
   10's frozen corpus. If every candidate's false pairs there outnumber its
   true pairs, the bet stops (trigger 0).
3. **The held-out set** (US4-US6): about 290 decision pages extracted from
   wiki-studio's own specs and pitches and two new memkernel spec directories,
   labelled by a session that never opens the audit code, reviewed by the
   owner, frozen.
4. **The measurement** (US7): the binding run on the held-out set and the
   report, published whatever it shows, as an evidence PR opened by hand.

Only with a pass does run 2 build the `possible-duplicate` kind (US9-US10) and
its ADR and documents (US11). The `for_root` switch fix (US8) is independent of
the verdict. No release step is part of either run.

- **FR-004 (the candidates, D3)**: One rule at three values of k: `mutual-top-1`, `mutual-top-3`, `mutual-top-5`. The unordered pair {A, B} is **flagged** at k when B is in A's first k and A is in B's first k. Each flagged pair carries both ranks (B's in A's list, A's in B's list). No score floor, no other candidate. The lists are computed once and every k is read from them.
- **FR-005 (labels, restatements and pair scope)**: A pair's label is its `pairs` or `cross_pairs` disposition in the set's `labels.json`, else `unrelated`; true = `redundant`, `conflicting`, `supersedes`. **A restatement** (the owner, 2026-11-27), decided from the two pages' `corpus.json` entries only: (a) both pages come from the same spec directory (`spec_path`'s directory); (b) one comes from a pitch (`spec_path` `specs/pitches/<id>/pitch.md`) and the other from a spec bundle of the same repository whose `origin_issue` (FR-008) is an integer equal to the leading number of the pitch id; or (c) both come from pitch files. A spec bundle with no `origin_issue` (on the held-out set, `wiki-studio-0-1-0` and `wiki-studio-0-6-0`) never meets (b) (plan, O3), and a memkernel bundle never does, since its `origin_issue` is not an integer. Every other pair is not a restatement. **Pair scope** (reported, not binding): `one-feature` when (a) or (b) holds, else `within-repository` when both pages share a repository, else `cross-repository`. On cycle 10's corpus there are no pitches and no `origin_issue` fields, so only (a) can apply.
- **FR-006 (the bar and the winner, D4)**: On the held-out set only, a candidate passes when all four hold: (1) the frozen labels hold at least **8** true pairs, else the verdict is `not testable`, never a pass; (2) it finds at least three quarters of the true pairs, rounded up, counted per true pair (`4 * found >= 3 * n`); (3) its false pairs do not outnumber its true ones (`false <= true`); (4) at least **2** of its found true pairs are not restatements. **Selection**: among passing candidates, the fewest false pairs per true pair wins (A beats B when `false_A * true_B < false_B * true_A`); a tie goes to the smaller k. **Verdict**: `winner`, `no candidate clears the bar` or `not testable`. **The winner line** of `report.md` is exactly one line: `Winner: mutual-top-1`, `Winner: mutual-top-3`, `Winner: mutual-top-5` or `Winner: none`.
