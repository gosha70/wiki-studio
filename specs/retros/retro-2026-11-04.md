## 4. What worked well

- **The external reviewer on most PRs and on the release page** (not on #57, and on #74 only in scoped passes; see section 1). It caught every retracted claim, the two release-page defects, the recorder's three findings and the early-closed issue before they spread. Verifying the reviewer's notes before acting (the stale "still open" release note) kept work from being redone.
- **Evidence PRs with one commit per protocol step, merged with a merge commit.** Each step is checkable on its own; the reviewer verified the range, the order and every hash.
- **Hashes against PyPI and the built artifacts**, and CI checked on the exact merge SHA before tagging.
- **Testing guards both ways.** The new resolve step was run against the old page (fails with `ResolutionImpossible`) and the new one (passes), and against an unreleased 0.8.2 bump. The recorder's interrupt test was proven to fail against the old handler.
- **Monitors on CI with every terminal state in the filter**, instead of polling.
- **Session memory notes** for driver bugs, closing keywords, the release-page checklist and the next-session plan; each one was used again within the session.
- **PR bodies through `--body-file`** from the scratchpad, and `closingIssuesReferences` checked after every PR opened since #68.
- **Writing the external brief from the tagged sources** with exact facts and a verify list; ChatGPT's own check then found the install conflict our docs had.

## Summary of proposed changes

1. infra-verification: shown-but-not-executed command blocks still get a real check (install lines dry-run).
2. Release checklist in the repo (release.yml header or docs/releasing.md): attach dist, hash against PyPI, absolute links.
3. Closing-keyword audit on hand-opened PRs.
4. auto-build driver: per-phase bypass record and honest summary; gate before `landed`; hill scopes moved per phase.
5. review runner: re-run a test a gating finding claims fails.
6. pitch-shaper and plan agents get `AskUserQuestion`.
7. Rules: precedent claims checked against git, tags or PyPI; PR state reported from `gh` (the same rule binds the reviewer).
8. An external review on record for the head SHA before a build PR merges (branch protection or the merge step).
