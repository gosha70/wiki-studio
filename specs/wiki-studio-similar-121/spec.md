## Why

Issue 121 asks whether wiki-studio can tell a curator that two pages record
the same decision. Cycle 10 measured a `findings` kind for it on a frozen
corpus of 299 extracted decision pages with 8 labelled true pairs: word overlap
of title and first paragraph found 3 of the 8, against the 6 the bar needed,
so nothing was built (`eval/duplicates/report.md`).

This bundle tries a different place: the moment a page is proposed. For each
new page, `propose` lists the few existing pages most like it, ranked by the
FTS5 ranker `find` already uses, so the proposer can read them and decide
whether the new page is a copy. It is a hint, never a finding: it never blocks,
never changes an exit code and calls no model.

It is measured first. Run 1 (US1-US3) writes the protocol (query rule, k,
which pages are compared, the direction rule and the bar) and freezes it before
any score exists; the owner signs it off; a script ranks the frozen corpus once
at a pause; the report publishes the result whatever it shows, as an evidence
PR opened by hand. Run 2 (US4-US6) builds the hint only with a pass: the
ranking function and the `plan.json` key, the CLI lines and the MCP result
key, the documents. No release step is part of either run.

## Constraints

- **Model-free, advisory, never blocking.** No model on any path, and none from `findings`, `approve` or `review_state`; the hint never blocks `propose` or `promote`, never changes an exit code, `review_state`, an approval or what `find` returns; no `findings` kind, no `lint` change.
- **One writer, no new contract.** `promoter.py` stays the only writer into the wiki; the hint writes only into the proposal directory (through `api.propose`) and the search cache beside the lock (through `search_index.py`). No frontmatter key, page type, directory, exit code, capability, MCP tool or runtime dependency; the `plan.json` keys and the MCP result key are optional and additive, as `fact_warnings` was; `plan.json`'s `version` stays 1.
- **`find` unchanged.** No change to `select`, `RankerConfig`, `DEFAULT_RANKER_CONFIG`, `ranker_config_hash`, the search cache format or `search_index.py`; the hint calls `select` as `find` does.
- **Measurement discipline.** The query rule, k, the slug rule, the direction rule and the bar are fixed in US1 and signed off before `rank.py` exists; nothing is scored on the corpus before that; nothing in the protocol changes after the run, and no second reading counts toward the verdict; `eval/duplicates/` and `eval/patterns/` are never edited; no new labels; no network read.
- **Script runs are main-session steps** (lesson of cycles 09 and 10). Auto-build sessions cannot run Python, so the ranking run (FR-014) happens at a milestone pause, committed by the main session as its own commit; hashes a phase records are computed with a shell `shasum -a 256`; every driver phase's tests pass on files that phase writes or an earlier commit holds.
- **No closing keyword** before an issue reference anywhere: not in this bundle, `eval/similar/`, the report, a commit message, PR text, docs or the CHANGELOG. Issues are written "issue 121". No PR closes issue 121 (D10).
- **No release step** in any run (FR-029).
- **Package boundaries.** Standard library only; changed package modules spell none of `tests/test_package_boundaries.py`'s forbidden layout strings, docstrings included.
- **Each phase is true on its own diff.** No file a phase writes states later-phase work as done: the protocol in US1, the script in US2, results and the report in US3, the library hint in US4, the surfaces in US5, the documents and the CHANGELOG entry in US6.
